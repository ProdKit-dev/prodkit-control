# ProdKit Control v0.7.0

v0.7.0 is the reliability and disaster-recovery milestone. It defines how the supported control/assurance profile recovers after site loss without converting missing or ambiguous evidence into success.

## Highlights

- Canonical Python, TypeScript and JSON Schema contracts for reliability profiles, backup manifests, restore plans/results, integrity findings/scans, break-glass grants/uses, uncertain-execution recovery, recovery-gap reconciliation, DR game-day evidence and recovery audit events.
- PostgreSQL schema 8 with tenant-scoped append-only recovery profiles, backup manifests, break-glass evidence, restore plans, integrity scans, uncertain-attempt reconciliation, RPO-gap reconciliation, restore results, game-day exercises and audit evidence.
- Governed standalone and PostgreSQL recovery services with four-eyes, short-lived capability-scoped break-glass authority.
- Database-clock validation of durable recovery authority and timing in the PostgreSQL profile.
- Component-level backup/restore coverage for ledger, lineage, configuration, artifact metadata, object store, idempotency ownership, execution attempts and governance state.
- Cryptographic signed-checkpoint verification against an independently supplied trust-root policy after restore.
- Fail-closed recovery of all durable terminal `UNCERTAIN` execution attempts; blind replay remains prohibited.
- Explicit reconciliation of the RPO gap between `recovery_point_at` and `failure_detected_at`, covering effects that may not exist in the restored database.
- Separate `FAILOVER` break-glass use required at final promotion, so earlier restore authority cannot silently become production-routing authority.
- PostgreSQL 18 schema 7 -> 8 migration qualification and deterministic DR game-day release gate.

## Reference reliability profile

The exercised enterprise warm-standby profile declares:

- RPO: **300 seconds**
- RTO: **3600 seconds**
- backup interval: no slower than RPO
- all eight recovery components required
- short-lived break-glass authority with independent approval

These values are the qualified repository reference profile, not a universal production SLA. Actual deployments must provision infrastructure and run scheduled restore exercises/game days that demonstrate their configured targets.

## Restore assurance boundary

A restore is promotable only when component digests, ledger chain tip, exact signed checkpoint, independent trust-root policy and object-store recovery all verify; every durable uncertain execution has been reconciled; the recovery-point gap has zero unresolved effects; actual RPO/RTO meet the active profile; and a live `FAILOVER` grant succeeds at promotion time.

The RPO-gap barrier is important because a backup can contain a complete database snapshot while still omitting external effects that occurred after its recovery point. v0.7.0 therefore does not infer “no lost side effects” from restored database state alone.

## Database compatibility

v0.7.0 advances the PostgreSQL schema from **7 to 8**. The supported milestone upgrade is:

`schema 7 -> schema 8`

Migration qualification preserves existing run and governance evidence while adding the recovery catalog. Runtime compatibility remains exact-schema/fail-closed. Downgrade is not claimed; use forward-fix or restore the pre-migration backup.

## Release gates

The candidate must pass the inherited CI, Security and CodeQL gates plus PostgreSQL 18 recovery qualification that exercises:

- schema 7 -> 8 upgrade preservation;
- append-only recovery evidence;
- tenant-negative reads and authority checks;
- break-glass capability, revocation, expiry and four-eyes semantics;
- real execution-attempt transitions to terminal `UNCERTAIN`;
- authoritative enumeration and reconciliation of uncertain attempts;
- independent signed-checkpoint/trust-root verification;
- RPO-gap reconciliation;
- isolated restore/game-day proof with zero blind replay and reference-profile RPO/RTO compliance.

Release publication remains gated by the repository's exact-source Trusted Release Proof, immutable tag/release publication and independent Release Verification workflow.

## Claim boundary

v0.7.0 implements and automatically qualifies the reliability/disaster-recovery engineering profile under the exercised reference conditions. It does not claim a universal availability SLA, independent DR certification, or completion of the v0.8 security/operational-hardening milestone. The previously unrecorded independent v0.5 tenant-isolation review remains a separate claim-language gate.
