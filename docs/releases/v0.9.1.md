# ProdKit Control v0.9.1

## Public readiness and end-user usability

v0.9.1 is a compatible patch release on top of the immutable v0.9.0 cumulative-completeness milestone. It does not move or rewrite the v0.9.0 tag. Its purpose is to make the repository and published release surface coherent, reproducible, understandable, and directly usable by public end users and contributors while preserving the v0.9 semantic/security boundary.

## Added

- A public getting-started guide covering supported distribution paths, first run, API development mode, deployment profiles, and release verification.
- A real programmatic dry-run example using the public Python action-broker/runtime surfaces.
- A machine-readable public-readiness contract and CI checker that binds current release documentation, package metadata, required public files, lifecycle workflows, and release notes to the exact release version.
- Explicit first-run smoke execution in Python CI and the release build: the full `prodkit-control demo` path and the public programmatic example must execute successfully before qualification/publication.
- Public contributor setup that reproduces the locked Python/TypeScript workspaces and explains the public fork CI path.

## Changed

- The root README is rewritten around the current v0.9.1 capability boundary instead of the stale v0.7 milestone text. It now documents language-neutral semantic authority, completed first-party package surfaces, supported deployment profiles, exact distribution claims, public security/support routes, and the v0.10.0 Production Candidate boundary.
- Current-facing security/support/release/versioning/lineage documentation is aligned with the v0.9.x implementation and release lifecycle while historical release notes and migrations remain immutable evidence.
- First-party Python and TypeScript package metadata is normalized for public distribution, including package README/license identity and canonical repository/homepage metadata.
- `make install` uses committed locks for both workspaces and `make check` exercises the same public/release contracts expected from contributors and release candidates.

## Distribution boundary

v0.9.1 supports:

- exact source checkout / exact GitHub source archive;
- the sealed GitHub Release package artifacts produced from the exact release source;
- source-based Docker builds using the repository's documented development/deployment configuration.

v0.9.1 does **not** claim public PyPI, npm-registry, or container-registry publication. Those channels may be added only after their own publishing identity, provenance, verification, rollback, and support expectations are explicitly qualified. This prevents an unverified registry channel from silently becoming a source of truth.

## Public security boundary

The public release continues to treat models/agents as untrusted proposers. Production credentials must remain outside model inputs and ambient untrusted runtime state. Privileged effects require authenticated identity, exact policy/approval binding, constrained executor capability, short-lived credentials where applicable, durable evidence, and independent reconciliation appropriate to the deployment profile.

ProdKit Control does not claim that application-level policy can make arbitrary hostile code incapable of escaping a compromised container, kernel, VM, microVM, hypervisor, or runtime. Isolation of untrusted code remains an independently enforced infrastructure boundary.

## Release assurance

v0.9.1 is eligible for publication only when the exact candidate proves:

- all first-party Python/TypeScript release versions and frozen locks agree on 0.9.1;
- package completeness remains closed with no first-party scaffold regression;
- every distributed Python package declares public README/license metadata and every TypeScript package declares public license/repository metadata;
- the current README, security/support docs, release note, and public-readiness contract agree on v0.9.1 and v0.10.0 as the next milestone;
- Python and TypeScript still pass the same language-neutral canonicalization/policy conformance corpus;
- the real CLI demo and programmatic example execute successfully;
- normal CI, Security, CodeQL, trusted exact-source proof, sealed publication, independent release verification, and verified branch cleanup all succeed.

## Claim boundary

v0.9.1 improves public usability, distribution metadata, documentation consistency, and release-consumer proof. It is not a new maturity milestone, does not weaken the v0.9.0 guarantees, and does not claim the v0.10.0 Production Candidate or v1.0.0 Production Assurance profile.
