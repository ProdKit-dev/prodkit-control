# ProdKit Control v0.6.1

## Purpose

`v0.6.1` is a safety correction for the immutable `v0.6.0` governance release. It closes late review findings discovered after `v0.6.0` had already been merged and tagged; the `v0.6.0` tag is not moved or rewritten.

## Safety corrections

- Evidence imports must consume an `EvidenceTransferVerification` produced by the offline verification path. Import receipts bind the exact verification ID, canonical verification digest, and independent trust-anchor digest.
- Destructive retention execution uses authoritative current time. Callers cannot supply a future evaluation timestamp to accelerate policy eligibility or retention deadlines.
- Retention batches reject duplicate `(resource_type, resource_id)` identities so each destructive decision remains paired with the exact candidate that was evaluated.
- Destructive retention records an append-only deletion intent before invoking an external deletion adapter.
- PostgreSQL commits that intent before the provider effect, then reacquires the tenant governance lock and revalidates current retention policy and legal holds immediately before deletion.
- If policy or legal-hold state changes between intent and execution, the deletion is cancelled and durable cancellation evidence is appended.
- If a provider effect or final database persistence becomes ambiguous after intent was committed, the durable intent remains available for reconciliation rather than disappearing with a rolled-back transaction.

## Compatibility

This is a patch release over `v0.6.0`. It does not introduce a new PostgreSQL schema version; schema 7 remains current. The supported upgrade window remains schema 5 -> 6 -> 7 and schema 6 -> 7.

The public import-receipt contract is strengthened to include verification provenance. Consumers that construct `EvidenceImportReceipt` directly or call `record_verified_import` must supply the verification evidence required by this release.

## Qualification

The exact release candidate must pass the normal ProdKit Control gates: Python 3.12/3.13/3.14, Node 22/24, PostgreSQL 18 governance and migration qualification, schema drift, strict typing, unit/integration coverage, Security, CodeQL, trusted release proof, publication, and release verification.

## Claim boundary

`v0.6.1` supersedes `v0.6.0` for deployments using governance retention deletion or evidence import. It does not expand scope into the v0.7 disaster-recovery/RPO/RTO milestone, and it does not change the separate independent-review boundary for v0.5 tenant isolation.
