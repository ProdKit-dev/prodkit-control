# ProdKit Control v0.8.0

## Security and operational hardening

v0.8.0 closes the roadmap's supported production-profile security/operations milestone while
preserving the existing provider-neutral architecture and v0.1.5 trusted release lifecycle.

### Security controls

- Canonical opaque `SecretReference` contracts plus tenant/purpose/audience/version enforcement.
- Short-lived workload identity policies and one-time assertion verification with atomic replay
  protection and adversarial race coverage.
- Hardened OIDC API token policy with required activation time, bounded lifetime, and optional
  authorized-party (`azp`) binding.
- Bounded HTTP abuse-control middleware returning `429`/`Retry-After`; health/readiness endpoints
  remain available to orchestrators.
- Structured security audit events and deterministic NDJSON export with credential-like field
  redaction.
- SLSA/in-toto provenance policy enforcing subject digest, trusted builder/build type, and a
  separately verified signature.
- Permanent Security CI policy checking dependency lockfiles, exact-SHA workflow/action pins, and
  Kubernetes hardening invariants.

### Operations

- Typed operational SLOs and burn-rate evaluation with reference paging/ticket thresholds.
- Incident classes, ownership, containment/patch targets, evidence requirements, and a deterministic
  CI incident exercise for replay, abuse, and supply-chain attacks.
- Kubernetes base hardening adds disabled service-account token automount, disabled service links,
  graceful termination, versioned image reference, and a PodDisruptionBudget on top of the existing
  non-root/seccomp/read-only/drop-capabilities baseline.
- Production hardening guide documents provider secret managers, workload identity, audit sinks,
  ingress limits, immutable image digests, network/database/storage controls, and executor
  isolation responsibilities.

### Release gates

v0.8.0 requires exact-head CI, Security, and CodeQL success. Security runs dependency audit, the
security-policy checker, and the deterministic incident exercise. Release promotion remains gated
by the immutable `prodkit-workflows` v0.1.5 proof/promotion/release/verification chain, and verified
release branches are eligible for automatic cleanup.

### Claim boundary

The repository provides standalone in-memory security primitives for development/test and
single-process use. Multi-replica production deployments must provide shared atomic replay/rate
control where required, a production secret manager, durable security-event retention/SIEM,
environment-specific network isolation, and immutable-digest deployment. Vendor products remain
optional integrations, not sources of truth for the ProdKit control model.
