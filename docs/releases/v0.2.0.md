# ProdKit Control v0.2.0

## Delivery-chain reconciliation

v0.2.0 closes the gap between controlled intent and the externally observed production world.

### Added

- Canonical external state-observation and audit-event contracts.
- Deterministic delivery-chain reconciliation with explicit matched, missing-evidence,
  unexpected-action, state-mismatch, conflicting-evidence, and unverifiable outcomes.
- Git, GitHub, CI/build, registry, deployment, Kubernetes, and database/control-plane adapters.
- Durable PostgreSQL reconciliation cursors, results, findings, audit-event deduplication, and
  tenant production-completeness profiles (schema version 4).
- Incremental scheduling with source cursors, freshness thresholds, exponential backoff, and capped
  retry delay.
- Tenant production-completeness assessment over required source health and reconciliation findings.
- Sanitized provider-contract fixtures and adversarial bypass/stale/conflict tests.
- Reconciliation SLO and escalation guidance.

### Assurance

The milestone is fail-closed:

- deliberate bypass activity produces high-severity `unexpected_external_action` findings;
- stale/unavailable evidence produces `unverifiable`, never `matched`;
- conflicting provider observations produce `conflicting_evidence`;
- repeated evidence ingestion and reconciliation are idempotent;
- exact release source must pass CI, Security, CodeQL, PostgreSQL 18, and Trusted Release Proof before
  publication.

### Compatibility

The existing v0.1.0 lineage model remains compatible. v0.2.0 adds an external-evidence reconciliation
layer and schema migration 4; it does not redefine the v0.1.0 controlled execution semantics.
