# ProdKit Control v0.0.1

`v0.0.1` is the first immutable release of ProdKit Control and establishes the canonical,
provider-neutral control-plane foundation.

## Included

- Canonical typed contracts for runs, events, actions, policy, approvals, execution,
  verification, reconciliation, artifacts, and lineage.
- Deterministic canonicalization and hash-chained event evidence.
- Fail-closed action brokering with policy and exact approval binding.
- Conservative ambiguous-execution handling: an executor exception records
  `execution.uncertain` and retains the idempotency claim rather than risking duplicate effects.
- Idempotent result reuse with fresh observation and verification evidence recorded in the ledger.
- Binding validation for execution results, observations, and verification results.
- Run lifecycle integrity: tenant validation and audit append occur before state mutation;
  completion is restricted to terminal statuses.
- Evidence ZIP verification with member/digest/sequence/hash-chain checks plus an optional
  externally trusted archive SHA-256 anchor.
- FastAPI adapter that fails closed unless an authenticated `PrincipalResolver` is configured;
  explicit development header authentication remains available only as an opt-in.
- Approval roles derived from authenticated principal claims and intersected with policy requirements.
- Python and TypeScript package surfaces normalized to `0.0.1`, generated JSON Schemas,
  strict typing/linting/tests, and reproducible locked dependencies.

## Deliberate boundaries

This release does **not** claim that every provider, executor, reconciler, signing adapter, or
external identity integration is production-complete. Several packages are stable extension
boundaries for later releases. In particular, durable recovery from ambiguous execution,
workload credential leasing, managed signing/key policy, external reconciliation, and a fully
hardened deployment profile remain roadmap work.

Evidence bundles in `v0.0.1` are internally tamper-evident. They are not described as
self-authenticating or cryptographically signed unless a caller supplies an external trust anchor
or a later signing integration.

## Verification

The tag release workflow verifies tag/version coherence, locked dependency state, formatting,
linting, strict typing, tests, generated schemas, TypeScript type-check/build, Python distribution
builds, and release-asset SHA-256 checksums before publishing the GitHub Release.
